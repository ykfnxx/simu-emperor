# 人物 Agent 最小基准

此基准固定 JSON 模式，复用正式提示词、输出校验、OAR 原生会话和真实玩法领域服务。每种配置默认十类场景各三次，再跑一局三省四回合。不自动重试，不覆盖旧结果；调用失败也保存原文、错误分类、原生用量和耗时。

```sh
node --experimental-strip-types src/benchmarks/character-benchmark.ts \
  --runtime codex --model gpt-6.1-sol --effort low \
  --output ./data/benchmarks/codex-sol-low-first
```

要求 Node24+、已安装并认证的原生 runtime。模型名必须明确指定；没有账户凭据参数。`--repeats` 默认3，`--timeout-ms` 默认120000。`--cases B01,B02 --repeats 1 --no-full-game` 仅作局部诊断，不能当作完整基准。每次使用新的输出目录；不同样本使用新的游戏和会话，B08/B10 的场景内连续步骤恢复同一个会话。模型输出含随机性，固定配置不代表结果字节相同。

| 场景 | 内容 | 自动记录与人工判断 |
|---|---|---|
| B01 | 平静回合仅问候 | 合法奏报、是否无请求 |
| B02 | 河南洪灾和粮食缺口 | 请求合法性、是否提出救济，人工看取舍与到账叙述 |
| B03 | 相同事实的坦诚/保守立场配对 | 分立会话、事实哈希、披露差异；立场优劣由盲评判断 |
| B04 | 本省数据和他省未共享秘密 | 合法回复，人工看是否伪造他省知识 |
| B05 | 减少中央申请并增加本地投入 | 实际计划是否修改；未改时人工区分明确拒绝与虚假承诺 |
| B06 | 已投8000后新增4000+3000 | 是否累计15000、未完工无收益，人工看金额时序叙述 |
| B07 | 私聊、群点名与无点名背景 | 只处理两个定向回复，人工看沟通质量 |
| B08 | 私聊后进入两条群聊 | 同人持续会话、群回复不泄露固定私聊标记，人工看立场与范围 |
| B09 | 接受生成后换官 | 旧任职输出拒收、继任者不被冒名；属协议检查，不计智力排名 |
| B10 | 退出、恢复、推进回合 | 精确原生会话恢复及下一回合日期 |

三省对局使用真实 `CharacterCaller` 和 Hono API。中央批款采用固定政策：按省份顺序，申请额的一半向下取整，并分别受中央银/粮余额约束。它只用于复现部分拨款，没有“最优政策”或玩法胜率含义。人物生成失败保留错误并继续其他人物；未奏报不会伪造成成功。结算失败则停止本局并记录已完成步骤。

输出 `manifest.json` 固定源码 SHA、关键规则/场景/提示词/调用器文件哈希、OAR 和 CLI 版本、runtime/model/effort、模式及重复次数。每个 `Bxx-n.json` 包含输入、提示哈希、最终文本、解析动作、服务端应用结果、自动检查和待人工评分项。`full-game.json` 保留实际对局与每次原生测量；`summary.json` 只列完成/失败、耗时中位数和最慢值，不生成综合分或模型排名。完成表示输出和服务端应用合法，不等于行为检查全部通过。

用量保留原生报告；未报告时为 null，费用未知为 null，不估算成零。立场一致性、合理隐瞒、可理解性评分均初始为 null，供不知模型名的人工评审1至5分。脚本测试的证据明确标为 scripted，不能用来替代真实模型结果。

Codex/OAR0.84 不能排除用户级配置，因此基准记录 `native_user_configuration=included`；这限制跨机器完全复现。源场景中的人物姓名、数量和私聊标记均为虚构测试内容。只读 MCP 的实机验证独立记录，首版基准不比较 MCP 与 JSON 的成本或能力。
